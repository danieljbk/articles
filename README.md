# articles

Personal article collection by Daniel Kwon. Static website at **https://articles.kwon.ai**. The collection is a directory of self-contained HTML files; each one is a standalone article — research notes, technical writeups, references — that Daniel has chosen to publish.

## What this is

- A simple **static website**. No framework, no CMS, no database. Articles are HTML files; the site is the HTML files.
- Hosted on **Cloudflare Pages**, deployed automatically every time `main` is pushed to GitHub.
- Each article is a single self-contained `.html` file: inline CSS, fonts loaded from Google Fonts CDN, no external assets. You can email an article file, drop it on a USB stick, or host it on any web server — it works as-is.
- The **landing page** at `articles.kwon.ai` is generated by `build.js` from the metadata of each article. It lists every article with its title, date, and one-line summary, sorted newest first.

## Where articles come from

Articles are generated during **Claude Code** sessions (Anthropic's terminal coding tool). Daniel asks Claude for structured information — a research brief, a technical comparison, a how-to — and Claude writes a self-contained HTML page in response. There is no manual authoring tool, no markdown pipeline, no editor: the HTML files in `pages/` ARE the articles, written directly.

Most articles start in the sibling [`articles-private`](https://github.com/danieljbk/articles-private) repo. When Daniel decides a piece is worth publishing, he tells Claude to "publish this," and the file is moved into this repo's `pages/` directory.

## Architecture: two repos

```
articles/           ← THIS repo. Public. Deploys to articles.kwon.ai.
articles-private/   ← Sibling repo. Private GitHub. Never deployed.
```

- **`articles/`** — every article in `pages/` here is published to the web.
- **`articles-private/`** — every article in its `pages/` stays local. It also generates a `local-index.html` listing articles from BOTH repos for unified local browsing.

The visibility boundary is the **repo**, not a subdirectory. There is intentionally no `private/` subfolder ignored by `.gitignore` — gitignore-based privacy in a single repo is one mistake away from leaking. Two-repo isolation makes leaks structurally impossible.

The apex domain `kwon.ai` is a different system entirely — a Cloudflare Workers app in [`danieljbk/kwon.ai`](https://github.com/danieljbk/kwon.ai). This repo only powers the `articles.` subdomain.

## Layout

```
articles/
├── pages/                          one self-contained HTML file per article
│   └── YYYY-MM-DD-short-slug.html
├── build.js                        zero-dependency Node script. Reads pages/, writes index.html.
├── index.html                      generated landing page. Committed.
├── README.md                       this file
└── .gitignore                      node_modules, .DS_Store
```

`index.html` is generated, but committed — so cloning the repo produces a working local copy without a build step, and GitHub's web file browser shows it.

## Article file conventions

For an article to appear on the landing page, its HTML must include these tags in `<head>`:

```html
<title>Article title here</title>
<meta name="date" content="YYYY-MM-DD" />
<meta name="description" content="One-line summary for the index." />
```

| Tag | Purpose | Required |
|---|---|---|
| `<title>` | Link text on the index | Yes |
| `<meta name="date">` | Sorts the index, newest first | Recommended (missing dates sort last) |
| `<meta name="description">` | Shown under the title on the index | Optional |

**Slug convention:** `YYYY-MM-DD-short-slug.html`. The date prefix sorts files chronologically on disk, matching the on-page sort order. Slugs are lowercase, hyphenated, descriptive.

## How to operate

### Add a new article

```bash
# Save the file with the right slug into pages/
cp path/to/article.html pages/2026-05-05-my-new-article.html

# Confirm <title>, <meta name="date">, <meta name="description"> exist in <head>

# Regenerate the landing page
node build.js
# → "Built index.html with N articles."

# Commit and push
git add . && git commit -m "Add: my new article" && git push
# Cloudflare Pages picks up the push and redeploys within ~30 seconds.
```

### Promote an article from private to public

The default authoring location is the sibling `articles-private/pages/`. To publish:

```bash
# from articles/
mv ../articles-private/pages/YYYY-MM-DD-slug.html pages/

# Regenerate both indexes
node build.js
(cd ../articles-private && node build.js)

# Commit and push both repos
git add . && git commit -m "Publish: <article title>" && git push
(cd ../articles-private && git add . && git commit -m "Promote to public: <slug>" && git push)
```

### Verify the site after deploying

- Visit `https://articles.kwon.ai` — should list every article, newest first.
- Click an article — should render with no broken assets.
- Check the Cloudflare Pages dashboard at `https://dash.cloudflare.com/` for recent deploys and their build logs.

## Cloudflare Pages configuration

| Setting | Value |
|---|---|
| Build command | `node build.js` |
| Build output directory | `/` (repo root) |
| Production branch | `main` |
| Custom domain | `articles.kwon.ai` (CNAME auto-managed because `kwon.ai` is on Cloudflare DNS) |

## How `build.js` works

Pure Node, zero dependencies. It does this and only this:

1. Reads every `*.html` file under `pages/`.
2. For each, regex-extracts `<title>`, `<meta name="date">`, `<meta name="description">`.
3. Sorts by date descending.
4. Writes `index.html` styled to match the article pages (Geist font, neutral palette, dark-mode aware via `prefers-color-scheme`).

If you want to change the index styling, edit the inline CSS template inside `build.js`. The articles in `pages/` are never touched by the build.

## Failure modes

| Symptom | Cause | Fix |
|---|---|---|
| Article doesn't appear on the index | Missing `<title>` or filename not `*.html` | Add `<title>`; rename file |
| Article appears but no description shown | Missing `<meta name="description">` | Add the tag, rerun `build.js` |
| Wrong sort order | Missing or malformed `<meta name="date">` | Use `YYYY-MM-DD` exactly |
| Site is stale after push | Cloudflare Pages build failed | Check Pages dashboard for failed deploys |
| Local `index.html` out of sync with `pages/` | Forgot to run `build.js` before committing | Run `node build.js`, recommit |
| Article renders but with broken styling | Missing `<link>` to Google Fonts CDN | Articles need their own fonts; use the standard template |

## History

Created May 2026. Daniel had been generating high-quality technical and personal documents in Claude Code sessions but losing them to `/tmp/` (which macOS auto-cleans). This system was designed so that those documents have a permanent, browsable, shareable home. Two-repo split (public / private) was chosen specifically because `.gitignore`-based privacy is one mistake away from leaking content; separate repos with different GitHub visibility cannot leak across that boundary.
